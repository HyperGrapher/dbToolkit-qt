Acceptance: all screens are coherent and accessible in every theme with no unthemed controls.

- [ ] **P06 — Windows services.** Detect existing database executables without relying solely on service display names. Associate services with connections and show running/stopped/pending/unavailable states. - [ ] **P07 — Database overview and offline snapshot.** After each successful refresh, atomically cache the selected service's database summaries, managed state, connection details, notes, ownership, size, table count, server version/settings, and refresh timestamp; never cache table rows. Show that snapshot while the service is offline, label it as cached with its age, and keep credential/connection-string reveal available after vault unlock. Disable live-data and mutation actions until the service reconnects. Do not imply PostgreSQL-style ownership for MySQL. Acceptance: cold offline startup shows the last snapshot, stale data cannot be mistaken for live state, limited privileges do not break the page, and reconnect refreshes the snapshot.
- [ ] **P08 — Creation and adoption.** Create databases with dedicated least-privilege users, generated passwords, and server-supported encoding/collation settings. Track partial server operations and preserve recoverable credentials; only compensate resources created by the operation. Persist managed state after confirmed server results once P04 is available; keep development secrets session-only before then. Adoption records supplied credentials without changing ownership or grants. Track whether the app created an associated user. Acceptance: project credentials access the intended database, adoption makes no server changes, and interrupted creation cannot silently lose credentials or claim success.
- [ ] **P09 — Maintenance.** Implement notes, managed-user password changes, empty database, recreate, and delete. Empty preserves schema; recreate removes all objects and produces a fresh database with recorded settings and project-user grants. Confirm exact destructive effects and targets, require typed names for database-wide destruction, and block system databases. Default optional user deletion off; block removal of shared users or when safety cannot be established. Do not silently terminate other clients or cascade outside the selected target. Acceptance: foreign keys, active sessions, partial failures, and password-update failures leave accurate server/vault state and recovery guidance.
- [ ] **P10 — Database selection and table browsing.** Do not display tables until a server connection and database are selected. Opening Table Viewer from a database carries that selection; opening it directly first shows a database chooser. Keep a server/database selector and breadcrumb visible in the viewer, clear table/row state when the database changes, and remember the last selection per session. Then provide schema/table navigation, column details, virtualized 100-row pages, server-side typed filters/sorting, and cell inspection/copy. Parameterize values and quote identifiers per engine. Use stable key ordering where available and explain page instability for tables without keys. Distinguish NULL, empty strings, binary values, and long text. Acceptance: no table query can run without an explicit database target; switching targets cannot leak stale rows; large tables and typed filters remain responsive and correct.
- [ ] **P11 — Editing.** Support explicit save/cancel for supported scalar values, empty strings where valid, and a separate Set NULL action. Require primary keys or suitable non-null unique keys for editing/deleting. Use transactions, original-value conflict checks, and affected-row checks; keep unsupported/generated/binary values read-only. Confirm row deletion and table emptying without cascading into unselected tables. Acceptance: composite keys work, concurrent changes are reported, and ambiguous rows cannot be modified.
- [ ] **P12 — SQL import/export and connection strings.** Discover compatible `psql`, `pg_dump`, `mysql`/`mariadb`, `mysqldump`, and `mariadb-dump` utilities, with manual path selection and engine/version checks. Export schema/data to SQL without global-user creation. Import an engine-native plain `.sql` file either into a newly created target or as a merge into an existing selected target. Create the new database separately using the user-entered name. Before execution, lexically inspect and normalize recognized dump-level `CREATE/DROP/ALTER DATABASE`, MySQL/MariaDB `USE`, and PostgreSQL `\\connect` directives so embedded database names cannot rename or redirect the selected target; reject dynamic or unsupported database-context changes before executing anything. Merge never rewrites row conflicts or silently overwrites data: stop on the first error, use one transaction where supported, and clearly report MySQL/MariaDB implicit-DDL commits and partial application. Show target, source dialect, compatibility, progress, cancellation, and results. Run tools without a shell, keep credentials out of arguments/logs, use protected temporary credential files, and clean them. Generate correctly escaped connection URIs. Acceptance: scripts naming another database still affect only the selected target; unsafe context switches are rejected; PostgreSQL failures roll back when eligible; MySQL/MariaDB partial results are accurate; each export restores into a disposable database; incomplete files are never presented as complete.
- [ ] **P13 — Tray workflow.** Add Show and Quit, then integrate Lock when P04 is implemented, using QApplication and notification-area support. Close minimizes to tray; without a tray it exits. Handle active mutations deliberately during shutdown and exclude credentials from notifications. Acceptance: restore, lock, quit, Windows session lock, and service disappearance behave consistently.
- [ ] **P04 — Encrypted vault (deferred until after P13).** Use SQLite in the user's application-data directory with libsodium Argon2id, a wrapped random vault key, and authenticated record encryption with fresh nonces. Persist versioned crypto parameters and make updates atomic. Encrypt administrator/root credentials, managed project credentials, connection details, cached database snapshots, notes, and identifying metadata; theme and other non-sensitive preferences may remain open. Implement first-run setup, unlock, manual lock, password change, and Windows session locking. Migrate memory-only development profiles into encrypted records only through an explicit save action; never write an interim plaintext store. No idle timeout. Hide sensitive views immediately, invalidate pending results, close connections, and clear secrets once active operations safely settle. No password recovery: explicitly confirmed vault reset leaves server databases untouched. Acceptance: first-use credentials persist encrypted and avoid later prompts, offline connection strings remain accessible only after unlock, wrong passwords and tampering fail safely, password changes survive restart, and no plaintext secrets appear in storage/logs.
- [ ] **P14 — Validate and package.** Produce a portable release folder under build containing Qt/QML and native runtime dependencies, licenses, usage instructions, export-tool setup, compatibility information, and troubleshooting. Validate MySQL 8.4, MariaDB 11.4, and PostgreSQL 16-18. Acceptance: the package works on Windows without developer tools and every PRD feature has recorded evidence.

## Acceptance and defaults

- Focused automated checks: vault tampering/migrations, offline snapshot age/state, SQL quoting/binding, import directive normalization/rejection, URI escaping, row identities/conflicts, theme completeness, partial-operation recovery, model transitions, and stale asynchronous results.
- Use explicitly configured disposable databases for destructive integration tests and export/restore verification. Never use an existing project database for those tests.
- Manual checks: keyboard use, resizing, 100/150/200% scaling, long identifiers, large tables, connection loss, missing utilities, UAC cancellation, and locking during operations.
- Inspect logs, local storage, process arguments, temporary files, and post-lock UI for credential exposure.
- Full PRD scope; existing installations and local connections only; elevation only for service control; portable delivery with app data in the user profile.
- No server installation, remote administration, interactive SQL console, schema design, or row insertion in this release. Engine-native plain SQL file import is included.
- No new library is planned. Use Qt process/file/model/settings APIs and installed engine-native client utilities. Do not enable vcpkg installation for this feature set.
- Merge conflict default: stop at the first error. Do not transform inserts into upserts or overwrite existing rows.
- Offline scope: cached database summaries and protected connection information only; never cache table contents.
- Keep interfaces small and use composition. Share engine implementations only where the behavior is genuinely common; represent engine capabilities explicitly.
